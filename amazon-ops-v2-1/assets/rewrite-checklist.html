卖点改写检查清单（表达落点口径）

2026-11-06 用户拍板 适用：Amazon / Temu / TikTok / SHEIN / eBay 全平台 配套校验：_check*.js 第39项 · check_listing.py ABSOLUTE_BANNED

用途：写或改写任何卖点（五点 / Highlights / 描述 / A+ 文案）时，逐项过一遍本清单。四步法是动作，红线是驳回条件，机器闸门是最后一道。

一句话原则

同一批已核实的事实，只换落点和主语——从「我有什么」改成「你不用担什么」。事实、数字、承诺一个都不新增。

客户是在「选错会怎样」上做比较，不是在「谁更专业」上做比较。功能罗列等于把可比较条目摆上桌，客户顺势比价；把同一条事实落到他要避免的失误上，卖点才从成本变成价值。

第一步 · 列「客户会犯的错」，不要先列功能

跨境 FBM 常见退货成因（逐条核对，非排序）——每条问自己：本产品能回应哪一条？

#客户会犯的错写法落点示例
1尺寸/容量买错引导看尺寸图；写「先量再买」（须先有准确尺寸数据）
2装不上 / 不会装写明结构与摆放方式（有图证才写）
3材质与预期不符（含气味）材质有出处才写；开放结构=看得见
4用几次就坏 / 承重不够只写有实测的承重；无数据一字不提
5与已有设备不兼容写清适配范围（有实测才写）
6到货赶不上时间点FBM 不写时效，除非有实测数据
7退换麻烦 / 售后找不到人描述里写使用边界，降低错买率
8配件缺失随包清单有资料才写
9颜色与屏幕显示有差多光源实拍图（图片层解决）

第二步 · 每个「错」回 facts 找一条硬事实

✅ 找得到 → 进入第三步落点改写
❌ 找不到 → 删掉这条错，不写。绝不反向：先想一句好听的话再去找依据。

出处仅限三种：facts 字段 / 产品实拍图 / 工厂或实测数据。「竞品也这么写」不是出处。

第三步 · 用三种句式落点（都要有依据支撑）

句式模板示例（须有依据）
消除担心No / Without + 客户怕的失误No wobble on uneven ground（依据：结构件/图片）
免除将就不用为了 X 将就Without giving up floor space（依据：收纳尺寸）
主动给边界Fits … / Made for … / 不适合 …Made for indoor use（依据：实测或工厂说明）
边界句（说清不适合什么）比承诺句更可信，且完全合规——这是「确定感」唯一的合法来源。

第四步 · 回查出处（逐词）

改写句里每个名词、每个数字，必须能定位到 facts 字段、图片或实测记录；查不到就退回功能原句——宁可朴素，不能悬空。

五点排序（与主攻词分配同一次做）

  • 第 1 条压最大的退货风险（通常是尺寸/适配）
  • 中间三条讲使用中会踩的坑
  • 最后一条处理「买了之后怎么办」（配件/组装/搬运/售后路径）
硬指标不变：每条 ≤500、Title Case 小标题 + 1–2 句、5 条主攻 5 个不同词、主攻词不与 Title 完整短语冲突。

四问自检（每条卖点过一遍）

#问题不过关的处理
1删掉 our / this 之后，句子还成立吗？成立 = 还在证明自己 → 换买方视角重写
2竞品能不能一字不改抄走？能 = 还是产品坐标 → 落到具体失误上
3客户读完知道自己「不用担什么」了吗？没有 → 回第一步重新对错
4每个数字与名词能回查到出处吗？不能 → 删词或退回原句

红线（人工驳回条件）

  • 禁止为了「托底感」新增任何承诺：guaranteed / warranty / 时效承诺 / 绝对化断言（never / won't break / no leak / rust-proof）。no X 句式仍是主张，同样要有依据。
  • FBM 业务：物流时效除有实测数据不写；保修除确实提供不写。
  • 不写价格、促销、与竞品对比（better than other brands）；不写 Best for（触发禁用词 best），改 Made for / For indoor use。
  • 禁用词表照旧（best / perfect / 100% / waterproof / heavy duty / non-toxic / eco-friendly / certified …）。
  • 变体属性词（颜色/尺寸/层数）不进父体共享字段（Title / Highlights / 五点 / 描述 / ST）。
  • 客户会验证（收货、量尺寸、组装）——错一句就是 1 星加退货。Listing 是事实场域，不是话术场域。

两个已知取舍（人工复核用）
① JS 版对 never 无条件拦截：never needs assembly 这类合法句会误伤 → 改写为 no assembly needed（前提：确实免组装）。
② Python 版对 won't 是全拦（无动词白名单）：won't fit 这类边界句会被判 ERROR → 人工复核后可放行，或改写为 fits where a full table will not 这类结构。

A+ 与图片：零承诺托底（优先级最高）

  • 尺码对照表 / 兼容清单 / 组装步骤 / 使用边界（不适合什么）——不承诺任何结果，只消除信息不对称，是全套文档里合规性最高的托底手段。
  • 图片同理：尺寸图、安装图解、内容物清单，全是「给确定性」而不是「给承诺」。
  • 出图提示词口径：不出现小孩；不画实物没有的功能；文字标注后期加。
