## 何时用 / 何时别用

**用**：给一个 ASIN 或产品资料要做整套页面 · 按第四版规范重写 Listing · 要主副图和 A+ 的作图提示词 · 要能直接粘后台的可复制字段页 ·（**用户明确要求时**）要广告方案（单文件 HTML）。

**别用**：只要单点数据查询 · 只做图片精修/去水印 · 只做成本损益核算 · 只要广告命名规则速查（直接看 `references/02`）。

## 四条铁律（违反即返工）

1. **不编造。** 尺寸、材质、数量、颜色、承重、防水等级、认证、兼容范围、包装配件、性能参数——只能来自产品图、产品资料或抓到的实测数据。缺就标 `待确认` 并列出要问的问题，不做「合理推测」。
2. **不写品牌名。** Listing 全文不含自有品牌名与他方品牌名、ASIN、竞品品牌、未授权兼容性表达。Brand 字段由各店铺后台单独填。
3. **硬指标先过机器。** Title ≤75 字符、Item Highlights ≤125 字符、Search Terms ≤250 字节、五点 5 条、核心词 100%/长尾 ≥80% 覆盖、一个词只主攻一个位置。**必须**跑 `scripts/check_listing.py` 拿到 PASS，不允许肉眼数。
4. **广告只做 SP。** SP（商品广告）以外的 SD、SB、SBV 一律不做，方案 HTML 的配置表与结构视图里都不出现（用户 2026-10-28 17:13）。脚本对非 SP 直接判 ERROR。
5. **广告默认不输出（用户 2026-11-06）。** 只有用户明确说「要广告方案 / 广告部分 / 广告结构」时才执行第 5 步；否则**不产出、不在回复里复述、不夹带广告口径**。默认交付范围 = 数据诊断 → Listing 13 段（含可复制页）→ 作图提示词（主副图 + A+，一份 MD）。此条优先于下文流程。

## 主流程（七步）

### 第 1 步：取数与诊断

用 Sorftime MCP 抓目标 ASIN：标题、五点、图片、A+、价格、评分与评论数、类目及排名、关键词。产出：一页数据快照 + 3-5 条诊断结论，每条挂到具体证据上。

**工具参数、字段口径、八个数据陷阱见 `references/04-sorftime-data.md`，动手前先读；换站点、换产品、遇到异常数据时再查 `references/07-field-notes.md`（本技能实测坑总表）。** 其中三条必须记住：

- `profit` / `profit_rate` 失真（成本按 0 算），**直接弃用**，只用佣金反推。
- `monthly_sales_volume` 是**父体级**，同父体子变体返回相同值，**不可相加**。
- 判定含垫/套装/配件，**必须看 `product_variations` 的属性名**，不能只看标题（曾因此把含垫价当成无垫价，定价带上沿错 30 英镑）。

**第 1 步的第一个动作永远是确认「这个产品到底是什么」**，不要沿用对话上一轮的假设。真实事故：客户给 ASIN 说要做体操杠全套，实际是婴儿高脚椅，前面所有产出作废。

- 自有链接优化 → 走 `references/03` 的 **P1**
- 参考竞对做新品 → 走 **P2**（只提取产品信息，**不输出、不照抄**竞对页面结构措辞）
- 无 MCP / 抓不到 → 要求用户提供后台导出或页面截图，**不允许凭印象补全**，该步标记「未验证」

**诊断五维**（每维一句结论 + 一个数字 + 一个动作）：

| 维度 | 看什么 |
|---|---|
| 市场结构 | 集中度（商品/品牌/卖家）、自营占比、退货率 |
| 需求与词 | 主词月搜索量级、ABA 周排名、建议 CPC、旺季月份；**季节性系数表（见下）** |
| 竞争位 | 同形态对手数量与价格带、我们现在的自然位 |
| 页面资产 | A+ / 视频 / 变体数 / 评论量，对比同价位对手 |
| 商业可行性 | 售价 × CVR vs CPC 的三角（能不能撑起广告） |

**数据诊断文件的「四、旺季与季节性」必须输出季节性系数表**（2026-11-27 用户定规）：主词取 3–5 个，用 `keyword_trend(type=2)` 的月度搜索量，最近 12 个完整月内最高月 = 1.0、其余 = 该月量 / 峰值四舍五入保留 1 位小数。算法、红线与命令见 `references/04-sorftime-data.md` 的「二·补」，用 `scripts/seasonality_index.py` 复算，不手工拍数。系数只用于淡旺季判断，**不写进 Listing 文案**。

### 第 2 步：Listing 文案（核心工序）

严格按 `references/01-listing-spec.md`，**顺序不可调换**：

```
关键词表（七类）→ 关键词分配（一个词一个位置）→ 定位分析 → Title → Item Highlights
→ 五点 → HTML 描述 → 纯文本描述 → Search Terms → 图片规范建议 → A+ 建议
→ 中文翻译 → 关键词覆盖核对表 → 自检结果
```

顺序不能换的原因：关键词表是后面所有模块的输入；先写文案再补词，必然堆砌。

**卖点表达落点（2026-11-06 用户确认，与本流程叠加使用）**：段落结构按「痛点 → 结构 → 好处 → 场景」，落点按四步法——先列「客户会犯的错」→ 回 facts 找硬事实 → 用三种句式（消除担心 / 免除将就 / 主动给边界）落到失误上 → 逐词回查出处。**只换表达落点，不新增任何无出处的事实、数字和承诺。** 完整方法见 `references/06-copy-placement.md`，供人逐项打勾的清单随技能自带在 `assets/rewrite-checklist.html`（项目机上另有正本 `D:\亚马逊运营模型\_刊登信息模板\卖点改写检查清单.html`，两份同源）；机器侧由 `scripts/check_listing.py` 的 `ABSOLUTE_BANNED` 拦截（2026-11-06 已并入 warranty / won't / rust-proof / leak-proof / unbreakable 等，注意对 `won't` 全拦，`won't fit` 类边界句人工复核放行）。

写完立刻校验，改到 PASS 再往下：

```bash
python3 scripts/check_listing.py {ASIN}_文案数据_{日期}.json --json-report {ASIN}_校验报告_{日期}.json
```

### 第 3 步：主副图提示词

> **与第 4 步共用一份文件**（用户 2026-11-08）：主副图与 A+ 提示词合并写入 `{ASIN}_作图提示词_{日期}.md`，**不要各出一份 MD**。文件顶部放「提示词速取区」，下面分「第一部分 主副图」「第二部分 A+」两节。

按 `references/03` 的 **P3**：主图 1 条 + 副图最多 6 条（场景/尺寸对比/细节特写/功能图解/包装内容/差异化对比，按产品特性选）。每条必须写全六要素：**画面主体 / 构图 / 风格 / 光线 / 色调 / 比例**，并附一句「这张图要说服买家什么」。

参考 `assets/listing-output-template.md` 第 9 节的字段。

**但要先分派**：不是每张都该用 AI 出成品。按 `references/05` 第二节判断 —— 需要「重复同一产品」「精确数字」「文字」的图（多档高度、多配置并排、尺寸标注），一律走 PS 合成或实拍，不要硬让模型画。经验：**8 张图里通常只有 5–6 张能纯靠 AI，其余必须人工合成。**

### 第 4 步：A+ 内容与作图提示词

按 `references/03` 的 **P5**：模块规划（视觉叙事顺序）+ 各模块中英文案 + 作图提示词（横幅比例、留文字区、不带文字）。

- A+ 的参数、卖点、场景必须与第 2 步终稿**完全一致**，Listing 终稿是唯一事实源。
- 未完成品牌注册 → 跳过并写明跳过原因。
- **图示详情按 `references/05` 执行**：先定卖点（每个都要有数据依据）→ 选图示类型（引线标注 / 图标条 / 数字块 / 分解图 / 尺寸对比 / 步骤图）→ 定标注位布局 → 出干净底图 → 交设计师叠字。
- **底图必须留标注位**：产品占画面中间 40%，左右各留 30%。提示词里写死这句，否则出图后没地方放字，只能缩产品、裁画面，整张作废。
- 提示词压到**四句**：锁产品 → 给环境 → 给光 → 给构图与留白。不写像素、不写数字、不写「不要文字」（见 `references/05` 第五节的分工具写法）。
- 交付给设计师的物料要齐四样：标注位示意图（`assets/callout-layout-template.svg`）、卖点文案表、排版参数表、底图提示词。
- **本步内容续写进第 3 步那份 `{ASIN}_作图提示词_{日期}.md` 的「第二部分 A+」，不另起文件**；两部分的标注位参数、卖点文案、事实源必须一致（都取自 Listing 终稿）。

### 第 5 步：广告方案（⛔ 默认不执行，需用户明确要求）

> 2026-11-06 口径：广告内容默认不输出，未明确要求时**直接跳到第 6 步**，不产出本节任何文件。
> 2026-11-08 口径：**广告的全部产出放在一个 HTML 里**，不再拆成方案 MD / 配置 CSV / 结构图三份（原来同一信息写三遍，是冗余的根源）。

复制 `assets/ads-plan-template.html`，把内嵌 `<script id="ads-data" type="application/json">` 换成该 ASIN 的数据，输出**一个文件**：

```
{ASIN}_广告方案_{日期}.html
```

页面固定四块，**同一信息只出现一次**：

| 区块 | 装什么 | 刻意不装 |
|---|---|---|
| ① 什么时候做什么 | 新品 / 成长 / 成熟三阶段：目标、预算、重点、推进条件 | 不列具体词和出价 |
| ② 照这个填后台 | 组合 / 活动 / 组 / 预算 / 竞价 / 匹配 / 关键词 / 出价 / 否定 / 阶段，一行一词 | 不写策略叙述 |
| ③ 长什么样 | 组合 → 活动 → 组 的层级与数量 | 不重复字段值 |
| ④ 什么时候停 | 触发条件 → 动作 | 不写「持续优化」这类空话 |

**命名与结构严格对齐 `references/02`**：

- 一个 SPU 一个组合；组合内活动必须同类产品；一个活动一般一个广告组。
- 全部英文 ASCII（§5.1–5.5）；自定义分类用 `[ ]`，不用 `【】`。
- **第二段标识符：有子 SKU 用子 SKU，没有 SKU 用子 ASIN**（2026-10-28 口径），不空着、不自造。
- **活动类型只到 SP**：`SP-AT` / `SP-MT-KT-EX|PH|BR` / `SP-MT-PAT-IP`。SD / SB / SBV 一律不出现。
- 组内关键词上限：大词 5 / 中词 10 / 长尾 50（§5.6，是上限不是最优）。
- **每个预算、每个出价都要有推导**：出价取 Sorftime 实测建议出价（`product_traffic_terms.recommended_bid` / `category_keywords` 的 CPC），标 `measured`；无实测值写 `待补充`。预算按阶段给并写明依据。拒收「建议预算 30–50 美金」这类无来源区间。
- 缺信息写 `待补充` 并集中列「待确认清单」，不留空、不填 0。

**校验（输入就是这个 HTML）**：

```bash
python3 scripts/check_ads_naming.py {ASIN}_广告方案_{日期}.html
```

`check_ads_naming.py` 会自动从 HTML 的 `<script id="ads-data">` 抽数据，**不需要另外交 naming.json**。

**怎么派工**：页面右上两个出口——「复制配置表」转制表符直接粘 Excel；「导出 CSV」存成文件（带 UTF-8 BOM，Excel 打开中文不乱码），适合发人或自己加跟踪列。**技能仍只产出一个 HTML，不额外交付 CSV / xlsx**。

### 第 6 步：合并单文件交付 + Listing 可复制页

**8a 可复制页（必做，用户 2026-11-06 定）**

除合并版之外，单独出一份 `{ASIN}_可复制页_{日期}.html`，只放要粘进后台的字段，每个字段一个复制按钮：

- Title / Item Highlights / **五点（拆成 5 个小块，每条一个按钮 + 另留「复制全部」）** / HTML 描述 / 纯文本描述 / Search Terms
- 关键词表、定位分析、中文翻译、覆盖核对、自检也各给按钮（粘 Excel 的用 Tab 分隔）
- **作图提示词（主副图 + A+）不放进这一页**，只留一个文件名指引：`{ASIN}_作图提示词_{日期}.md`（两者已合并为同一份 MD）
- 复制按钮要带 `navigator.clipboard` 失败回退（`document.execCommand('copy')`），否则本地 file:// 打开时按钮无效
- HTML 描述复制出来要是**真实标签**（页面里显示时转义，复制时取 `innerText`）

**8b 合并版**

前面各步产出的是分散文件，用户实际要的是「一份能从头翻到尾的东西」。用 `assets/full-delivery-template.html` 做一份合并版：同样分章、顶部 sticky 导航、内容与各独立文件**同源**。广告未要求时，合并版**不含广告章**。
> 合并版里主副图与 A+ 可以分成两章展示（便于阅读），但**章节数 ≠ 文件数** —— 独立 MD 只有一份 `{ASIN}_作图提示词_{日期}.md`，两章内容都取自它。

**工程做法（必守）**：单文件超过约 30K 字符时，**一次性 Write 会失败**（实测 27K 已写不出、36K 直接无输出）。改为：

```bash
# 1) 分 4-6 段写入 _part1.html … _partN.html
# 2) 用 python 拼接（不要用 shell cat，避免编码问题）
python3 - <<'EOF'
import io
parts = ["_part%d.html" % i for i in range(1, 6)]
html = "\n".join(io.open(p, encoding="utf-8").read() for p in parts)
io.open("{{ASIN}}_{{站点}}_全部交付.html", "w", encoding="utf-8").write(html)
print(len(html))
EOF
# 3) 校验结构后用 rm 删掉 _partN.html
```

拼接后必须校验标签闭合（写个 HTMLParser 数开闭），`section` 开闭数量要相等。

### 第 7 步：一致性闸门（合并后必跑）

同一份内容在交付里通常有 **5 个副本**：`{ASIN}_文案数据_{日期}.json`、文案正稿 MD 的英文与中文译文、`{ASIN}_作图提示词_{日期}.md`、合并 HTML。改了一处漏了另一处，肉眼极难发现。

```bash
python3 scripts/check_consistency.py <交付目录> --json-report consistency.json
```

它查这些（都是真实出过错的地方）：

| 检查 | 抓什么问题 |
|---|---|
| `MD_MISSING` | 改了 json 没同步 md（五点、描述、Highlights 任一） |
| `DESC_DRIFT` | HTML 描述与 Plain 描述**逐段**不一致 |
| `BULLET_COUNT` | 五点不是 5 条 |
| `NON_SP` | 广告方案混进了 SD / SB / SBV（从 HTML 内嵌 `ads-data` 读，无需 naming.json） |

## 文档口径问题（落地前必读）

以下是原文自身的问题，本技能**如实标注、不自作解释**：

1. **广告规范章节缺失**：原文编号「二、总体原则」直接跳到「五、规范内容」，**三、四节不存在**（很可能是产品分级与颗粒度规则）。本技能只实现现有文本，不补写；遇到需要分级判断的场景（能不能投 SB/SD、能不能放大颗粒度）一律标 `待确认`，回问规范编写方。
2. **「只用英文」与示例矛盾**：正文写「所有命名中都只能使用英文，不可以出现中文」，但示例用中文自定义内容与前缀 `【】`（`Leo-A0001A-SP-MT-EX-【长尾词】-【防御】`）。
   → 本技能默认取「正文」：自定义内容转英文、`【】` 改 ASCII `[]`（如 `[LongTail]`、`[Defend]`）。这属于对示例的偏离，**交付物里必须显式声明**，让规范方有机会反驳。
3. **活动命名单店/多店两条规则文字完全相同**，未体现差异；示例里第二段填的是子 SKU 代码（`A0001A`）。
   → **已按用户 2026-10-28 口径定死**：第二段标识符取 **子 SKU**；**没有 SKU 的直接用子 ASIN**；两者都拿不到才用占位符并标待确认。不要空着、不要自造编号。
4. **示例有重复行**：`Leo-A0001A-SP-AT`、`...-SP-MT-BR-【Plam-tree】` 各出现两次。按「组名 = 活动名 + 自定义分类」推断是活动与同名组的成对写法，不要照抄成两个活动。
5. **缩写表未定义 `PT`**，但常用组合里出现 `SB-PC-NLP-PT-IP`。按原文照写，不自行解释该缩写。

### 业务口径（不是原文问题，是本公司的执行收紧）

6. **广告只做 SP**（用户 2026-10-28 17:13）：SD / SB / SBV 全部不做。这比原文「新品 16 周内不做 SD/SB」更严，两者不冲突；缩写表里 SD/SB 相关条目仍保留，只为读懂规范原文，不作为产出依据。
7. **命名第二段标识符**：子 SKU 优先，无 SKU 用子 ASIN（见第 3 条）。
8. **命名自定义内容全英文 + ASCII 方括号**（见第 2 条），交付物需声明该偏离。
