# 提示词流程模板（《亚马逊广告提示词-草稿》）

> 原文路径：`桌面/亚马逊SKILL第二版/亚马逊广告提示词-草稿.docx`
> 原文是一份「自己用的提示词清单」，本文把它改成**带变量占位的可复用模板**，措辞与要求保持不变，只补了变量位和执行说明。
> 变量约定：`{ASIN}` `{SITE}` `{站点中文名}` `{OP英文名}` `{产品名}` `{产品资料}`

## 流程总览（六步）

| 步骤 | 模板 | 谁执行 | 产出 |
|---|---|---|---|
| 1 | P1 / P2 取数 + 写页面 | 技能自动 | 数据诊断 + Listing 全文（13 段） |
| 2 | P3 主附图提示词 | 技能自动 | 主图 1 条 + 副图 ≤6 条提示词 |
| 3 | P4 出主附图 | **人工到 ChatGPT** | 实际图片 |
| 4 | P5 A+ 图与文案提示词 | 技能自动 | A+ 模块规划 + 文案 + 提示词 |
| 5 | P6 出 A+ 图 | **人工到 ChatGPT** | 实际 A+ 图 |
| 6 | P7 广告方案（单文件 HTML） | 技能自动 | 一个 HTML：结论 / 阶段 / 配置表 / 结构 / 止损 |

> ⚠️ 第 3、5 步**必须人工完成**：原文明确「上传提示词 + 上传产品实拍图/产品现有图」到 ChatGPT 出图。技能不得假装已生成图片。
> 2026-11-08 口径：第 2、4 步在流程上仍是两道工序，但产出**合并写入同一份** `{ASIN}_作图提示词_{日期}.md`（顶部速取区，下分「主副图」「A+」两部分），不各出一份 MD。

## P1 基于自己现有链接重写页面

```
使用 Sorftime MCP 调用并分析亚马逊{站点中文名}产品页面（https://www.amazon.{域名}/dp/{ASIN}），并输出一套完整的页面优化方案。需完成以下任务：

1. 通过 Sorftime MCP 抓取并解析该 ASIN（{ASIN}）在{站点中文名}的完整产品详情数据，涵盖标题、五点描述（Bullet Points）、产品图片、A+ 内容、价格、评分与评论、类目及排名、关键词等信息，并对各项数据进行结构化整理与简要诊断。
2. 参考《亚马逊 CHATGPT 写页面（第四版）》文档中的页面撰写规范与要求，基于上述抓取与分析结果，撰写一份完整的亚马逊产品页面文案。
```

**用途**：以自己现有链接为起点做优化。诊断必须挂到抓到的数据上，不能空谈。

## P2 基于参考竞对信息写页面

```
请通过 Sorftime MCP 抓取并解析亚马逊{站点中文名} ASIN {ASIN}（https://www.amazon.{域名}/dp/{ASIN}）的完整产品数据，仅提取产品信息（不输出页面结构），信息需涵盖：标题、五点描述、产品图片、A+ 内容、价格、评分与评论、类目及排名、关键词。

随后参照《亚马逊 CHATGPT 写页面（第四版）》文档的撰写规范与要求，基于抓取与分析结果，按该文档模版输出一份完整的亚马逊产品页面文案。输出需结构清晰、信息完整，并严格遵循文档规范。
```

**用途**：参考竞对做新品页。刻意要求「不输出页面结构」，避免照抄竞对排版措辞。

## P3 主附图（主图 + 副图）提示词

```
根据 Sorftime MCP 产品的市场定位分析，为我的亚马逊产品撰写一套主图与附图的文案，并额外提供一份用于 AI 作图的提示词。

围绕主附图的各个模块，规划其内容主题与图片用途，形成完整的视觉叙事顺序，并清楚说明每个模块要传达的信息和它在整体叙事中承担的视觉作用。

另外，附上可直接用于图像生成的提示词，明确画面主体、构图、风格、光线、色调与比例要求，以便准确生成与文案匹配的图片。
```

**验收**：每条提示词六要素齐全（主体 / 构图 / 风格 / 光线 / 色调 / 比例），且每张图配一句「这张图要说服买家什么」。主图必须纯白底、产品占比 ≥85%（见 §7 图片规范）。

## P7 广告方案（单文件 HTML）

> **2026-11-08 用户口径**：广告的全部产出放在**一个 HTML** 里，不再拆成「方案 MD + 配置 CSV + 结构图」三份。
> 原文 P7 分 a/b/c 三段提示词，本技能合并为一次输出；提示词原意保留（见下），只改承载形态。

### 原文提示词（三段，保留备查）

**P7-a 广告投放建议方案**

```
产品 OP 是：{OP英文名}

基于上面 Sorftime MCP 产品分析得出的产品定位、产品词，制定一份完整的亚马逊广告投放建议方案，内容包括：
产品定位与目标受众分析、关键词策略（核心词、长尾词、竞品词、否定词清单）、广告活动结构（自动广告、手动广告、商品推广的组合与预算分配）、出价与竞价策略、分阶段投放计划（新品期、成长期、成熟期）、ACOS 与 ROAS 目标设定、数据监控与优化节奏，以及 Listing 与广告的协同优化要点。

输出以中文呈现，条理清晰，具备可执行性，并针对该 ASIN 给出具体建议而非通用模板。
```

**P7-b 广告组逐条配置**

```
并根据上面 Sorftime MCP 结果给到的广告建议，按指定广告命名规则（见《广告管理规范V1.0》）为每个广告组生成完整配置，逐组输出以下字段：

Ad group name、Campaign name、每日预算、广告活动、广告投放定位（自动/手动）、广告活动的竞价策略（动态竞价-只降低/动态竞价-提高和降低/固定竞价）、投放关键词、Match type、TARGETING GROUPS、Negative keyword/Negative product、Bid adjustments

确保同一 Campaign 下的广告组命名保持一致，字段取值符合各平台的规则与限制，缺失信息时标注待补充项，输出结构清晰、便于直接使用。
```

**P7-c 广告结构示意图**

```
最后再到广告结构示意图，单独放一个 HTML
```

### 落地改法（本技能实际执行）

原文这三段是「一次把话说全」的写法，落地时必然互相覆盖——同一份命名、预算、出价、否定词，要在方案里讲一遍、配置表列一遍、结构图再画一遍。本技能合并为单页四块：

| 区块 | 对应原文 | 承载内容 |
|---|---|---|
| ① 什么时候做什么 | P7-a「分阶段投放计划」 | 新品/成长/成熟：目标、预算、重点、推进条件 |
| ② 照这个填后台 | P7-a「活动结构+预算+出价」+ P7-b 全部字段 | 一字一行的配置表，可复制 TSV / 导出 CSV |
| ③ 长什么样 | P7-c | 组合 → 活动 → 组 的层级与数量 |
| ④ 什么时候停 | P7-a「数据监控与优化节奏」 | 触发条件 → 动作 |

**有意舍弃的原文要求**（都有理由，不是漏做）：

| 原文要求 | 处理 | 原因 |
|---|---|---|
| 产品定位与目标受众分析 | 不重复写 | 第 2 步「定位分析」已产出，方案引用即可 |
| 关键词策略（核心/长尾/竞品/否定清单） | 只在 ③ 配置表出现 | 第 2 步已有七类词表；再写就是第三份副本 |
| ACOS / ROAS 目标设定 | 不产出具体目标值 | 原文无计算支撑、只能拍数；本技能不写无依据数字，改用实测出价 + 止损规则约束 |
| Listing 与广告协同优化要点 | 不单独成节 | 属第 2 步范畴 |

**命名与结构仍严格按 `references/02`**：

- 命名格式 `{OP英文名}-{子SKU 或 子ASIN}-SP-{投放形式 1-4 段}-[自定义内容]`，广告组名 = 活动名 + `[自定义分类]`，全部 ASCII。
- 第二段标识符：**有子 SKU 用子 SKU，没有 SKU 用子 ASIN**（用户 2026-10-28）。
- 类型段恒为 `SP`：**SD / SB / SBV 不做**（用户 2026-10-28 17:13）。
- 原文「广告活动结构」覆盖的自动/手动/商品推广，**全部属于 SP 内部形式**。

单页模板：`assets/ads-plan-template.html`；校验：`scripts/check_ads_naming.py <广告方案.html>`（自动读内嵌 `ads-data`）。
