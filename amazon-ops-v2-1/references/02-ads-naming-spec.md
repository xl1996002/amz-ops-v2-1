# 亚马逊广告管理规范（《广告管理规范V1.0》）

> 原文路径：`桌面/亚马逊SKILL第二版/广告管理规范V1.0.docx`
> **注意**：原文编号从「二、总体原则」直接跳到「五、规范内容」，**三、四节在原文件中缺失**。本文件只实现原文确实存在的内容，不替文档补写。
> 原文亦未给出产品分级（P 级 / B 类）判定标准，因此本技能不做任何分级假设。

## 一、目的

提升广告管理效率，统一广告结构。

## ★ 广告类型范围（本技能强制，用户 2026-10-28 17:13 指令）

**只做 SP（Sponsored Product / 商品广告），SD、SB、SBV 一律不做。**

- 广告方案、广告组配置、结构图里**不出现** SD / SB / SBV 类型的活动。
- 缩写表里的 SD / SB / SBV / PC / AUDT / VRC / VRP 等仍保留（用于读懂规范原文与他人方案），但**本公司方案不产出**。
- 用户要求做展示广告或品牌广告时，先确认是否已解除这条限制；未解除则只出 SP 部分，把 SD/SB 标为「范围外，不做」。
- 原文「新品上架 16 周内不允许做 SD、SB」是限制上限；本口径比原文更严，等于**任何阶段都不做**，因此该闸门在实际交付中不会触发，但仍需在方案里写明依据（避免被误读成漏做）。

## 二、总体原则

- 一个 **SPU** 创建一个广告组合（Portfolios）。
- 一个广告组合下可以有多个广告活动，但**必须都是同类产品**。
- 一个广告活动**一般只有一个广告组**（Groups）。
- 若一个广告活动需要对应多个广告组，则在广告组命名的**投放形式后面加自定义说明**。
- **所有命名中都只能使用英文，不可以出现中文。**
- **广告活动类型只到 SP 一层**（见上）。

## 五、规范内容

### 5.1 广告组合命名（Portfolio）

| 情形 | 命名规则 |
|---|---|
| 一个 SPU 只在一个店铺运营 | `运营人员英文全名-ASIN` |
| 一个 SPU 在多个店铺运营 | `运营人员英文全名-子ASIN` |
| 现有父 ASIN 对应多个 SPU | 使用 **Amazon 的父 ASIN** 命名（为评论合并变体的，需单独分开命名） |

> 组合层沿用原文用 ASIN；**如果该 SPU 还没有 ASIN（未上架、只有内部 SKU）**，就用 SKU 代替，规则同 §5.2 的标识符优先级。

### 5.2 广告活动命名（Campaign）

| 情形 | 命名规则 |
|---|---|
| 一个 SKU 只在一个店铺 | `英文名-子SKU-投放形式缩写-[自定义内容]` |
| 一个 SKU 在多个店铺 | `英文名-子SKU-投放形式缩写-[自定义内容]` |
| **没有 SKU 的（竞品、未建编码、代运营未接 ERP 等）** | `英文名-子ASIN-投放形式缩写-[自定义内容]` |

**第二段标识符取值优先级（用户 2026-10-28 明确）**：

```
子 SKU  >  子 ASIN  >  （父 ASIN）  >  占位符待确认
```

> 有 SKU 就用 SKU；**没有 SKU 的直接用 ASIN**，不要空着、也不要自己造编号。
> 原文这两行规则文字完全一致，未体现单店/多店差异，本表按「标识符类型」重写以消除歧义。
> 标识符是「命名依据」，不等于投放范围 —— 一个子 ASIN 的活动仍然只投该子体。

投放形式缩写一般分为 **3-5 段**，用英文缩写，并用 `-` 分隔。

### 5.4 常用组合（原文）

**商品广告** ← 本技能只用这一段

- 自动投放：`SP-AT`
- 手动投放：`SP-MT-KT-EX`、`SP-MT-KT-PH`、`SP-MT-KT-BR`
- 定位广告：`SP-MT-PAT-IP`

**展示广告**　⚠️ 不产出，仅列原文

- 自动投放：`SD-AT`
- 定位广告：`SD-PAT-IP`
- 再营销广告：`SD-AUDT-VRC`、`SD-AUDT-VRP`、`SD-AUDT-AA`

**品牌广告**　⚠️ 不产出，仅列原文

- 定位广告：`SB-PC-NLP-PT-IP`（原文如此，`PT` 未在缩写表中定义）
- 关键词定位着陆页：`SB-PC-NLP-KT`

### 5.5 广告组命名

`广告活动名称-[自定义分类]`

组名**整段继承活动名**（含其中的 SKU / ASIN 标识符），只在其后追加 `[自定义分类]`，不再单独写 SKU 或 ASIN。

### 5.6 广告组关键词数量上限（按 ABA 排名判定）

| 关键词类型 | 数量限制 | US | UK | DE |
|---|---|---|---|---|
| 大词 | 5 个 | 2 万以内 | 2 千以内 | 1.2 万以内 |
| 中词 | 10 个 | 2 万–10 万 | 2 千–1.5 万 | 1.2 万–5 万 |
| 长尾词 | 50 个 | 大于以上排名 | 大于以上排名 | 大于以上排名 |

> 原文注明：**这不是最优方案，只是最大限制。原则上广告组关键词越少，可以管理得越精细。**

### 5.7 自定义分类写法（四选一或组合）

- 按大词、中词、小词分类
- 直接写具体的关键词
- 直接写具体的投放 ASIN
- 加广告目的（防御 / 进攻）

### 5.8 归档

广告活动关闭的，需把广告活动放入 **`英文名-广告归档`** 这个广告组合内。

### 5.9 原文示例

运营 Leo，SPU `A0001`，下面 2 个 SKU `A0001A` / `A0001B`：

```
广告组合：Leo-A0001

广告活动 / 广告组：
Leo-A0001A-SP-AT
Leo-A0001A-SP-MT-BR-【Plam-tree】
Leo-A0001B-SP-AT
Leo-A0001B-SP-AT-【紧密】
Leo-A0001B-SP-AT-【关联】
Leo-A0001B-SP-AT-【补充】
Leo-A0001B-SP-MT-EX-【长尾词】
Leo-A0001B-SP-MT-EX-【长尾词】-【防御】
Leo-A0001B-SP-MT-EX-【长尾词】-【进攻】
```

> 原文该示例中 `Leo-A0001A-SP-AT` 与 `...-SP-MT-BR-【Plam-tree】` 各出现两次（原文如此）。按 5.5「广告组 = 活动名 + 【自定义分类】」推断，应理解为「活动名 + 同名广告组」两行，或同活动下两个组。落地时按实际广告组数量成对输出，不要照抄重复行。

## 5.10 原有广告结构调整

- **新品全部需要按新结构执行。**
- 无论新品还是老品，**广告组合**都要按新要求来，按产品把广告活动放入对应组合。
- 广告活动内有多个 SKU 的，需识别是重要产品还是非重要产品。
- 广告组合命名规则不变。
- 广告活动需看本身 ACOS：
  - ACOS 已很高（**大于 50% 且已运行超过 4 周**）→ 可以重建广告活动，把原活动停掉。
  - ACOS 很好 → 广告活动命名规则同广告组合，用 **SPU** 命名。
- 广告活动内有多个 SPU 的（SPU 定义 = 一个产品系列）→ **必须重建广告活动**。
- 一个广告组内有多个 SKU 的，处理方案同上。
- 所有调整后不用的广告活动按归档规则归档。

## 六、其他要求

- **新品上架 16 周内，不允许做 SD、SB 类广告。**
  > 本技能口径更严：**只做 SP，任何阶段都不做 SD/SB**（见开头「广告类型范围」）。
- 产品转移 OP 的，需在转移的 **3 个工作日**内，重新命名所有广告组合、广告活动、广告组。

## 附：机器校验

命名合规（纯 ASCII、缩写段、组名前缀、关键词上限、**只做 SP**）用脚本跑，不靠肉眼：

```bash
python3 scripts/check_ads_naming.py naming.json
```

脚本对 `type` 为 SD / SB / SBV 的活动直接判 ERROR（`NON_SP`），不会放行。

输入结构见脚本文件头注释。
