# 卖点表达落点（2026-11-06 用户确认）

> 从原 `amazon-listing-copy-fourth-edition` 技能合并而来。适用于 Amazon 及 Temu / TikTok / SHEIN / eBay 的卖点表达。
> 可执行清单（给人逐项打勾用）：技能内自带 `assets/rewrite-checklist.html`（原《卖点改写检查清单》，直接用浏览器打开；项目机上的正本在 `D:\亚马逊运营模型\_刊登信息模板\卖点改写检查清单.html`，两份内容一致）

## 一句话原则

**同一批已核实的事实，只换落点和主语——从「我有什么」改成「你不用担什么」。事实、数字、承诺一个都不新增。**

客户是在「选错会怎样」上做比较，不是在「谁更专业」上做比较。功能罗列等于把可比较的条目摆上桌，客户顺势比价；把同一条事实落到他要避免的失误上，卖点才从成本变成价值。

## 四步法

1. **先列「客户会犯的错」，不要先列功能。** 跨境 FBM 常见退货成因（逐条核对，非排序）：尺寸/容量买错 → 装不上或不会装 → 材质与预期不符（含气味）→ 用几次就坏或承重不够 → 与已有设备不兼容 → 到货赶不上时间点 → 退换/售后找不到人 → 配件缺失 → 颜色与屏幕显示有差。
2. **每个「错」回 facts 找一条能回应的硬事实。** 找不到就删掉这条错、不写。绝不反向：先想一句好听的话再去找依据。
3. **用三种句式落点**（三种都必须由已有事实或图片支撑）：
   - 消除担心：`No wobble on uneven ground`（依据：结构件 / 图片）
   - 免除将就：`Without giving up floor space`（依据：收纳尺寸）
   - 主动给边界：`Fits tables up to 120 cm` / `Made for indoor use`（依据：实测或工厂说明）
4. **回查出处。** 改写句里每个名词与数字，必须能定位到 facts 字段或图片证据；查不到就退回功能原句——宁可朴素，不能悬空。

## 五点顺序

不按「功能 1–5」并列，按客户决策顺序排：第 1 条压最大的退货风险（通常是尺寸/适配）→ 中间三条讲使用中会踩的坑 → 最后一条处理「买了之后怎么办」（配件/组装/售后路径）。**硬指标不变**：每条 ≤500、Title Case 小标题 + 1–2 句、5 条主攻 5 个不同词。

## 零承诺托底：A+

尺码对照表、兼容清单、组装步骤、使用边界（不适合什么）——这类内容不承诺任何结果，只消除信息不对称，是全套文档里合规性最高的托底手段。DE 站已用「描述写不适合什么」换退货率，可推广到所有站点。

## 四问自检（每条卖点过一遍）

1. 删掉 `our` / `this` 之后，句子还成立吗？成立 = 可能还在证明自己。
2. 竞品能不能一字不改抄走？能 = 还是产品坐标。
3. 客户读完知道自己「不用担什么」了吗？
4. 每个数字与名词，能回查到出处吗？

## 红线（违反即驳回）

- **禁止为了「托底感」新增任何承诺**：guaranteed / warranty / 时效承诺 / 绝对化断言（never / won't break / no leak / rust-proof）。`no X` 句式仍是主张，同样要有依据。
- FBM 业务：物流时效除有实测数据不写；保修除确实提供不写。
- 不写价格、促销、与竞品对比（`better than other brands`）；不写 `Best for`（触发禁用词 best），改 `Made for` / `For indoor use`。
- 禁用词表照旧，任何改写后必须重跑 `check_listing.py`。**机器侧已把同类禁词并入 `ABSOLUTE_BANNED`**（见下「机器闸门」）。
- 客户会验证（收货、量尺寸、组装），错一句就是 1 星加退货。**Listing 是事实场域，不是话术场域。**

## 机器闸门

| 流水线 | 拦什么 | 位置 |
|---|---|---|
| Python（本技能） | `ABSOLUTE_BANNED`：never / guaranteed / warranty / won't / unbreakable / indestructible / rust-proof / leak-proof / bulletproof / any weight | `scripts/check_listing.py` |
| JS（项目 `Listing_*/_工作脚本`） | 第 39 项 [A]，口径同上，但 `won't`/`will not` 仅在后接晃断漏锈类动词时命中 | `_check*.js` |

**两个已知取舍**：
1. JS 版对 `never` 无条件拦截，`never needs assembly` 这类合法句会误伤 → 改写为 `no assembly needed`（前提：确实免组装）。
2. Python 版对 `won't` 全拦（无动词白名单），`won't fit` 这类边界句会判 ERROR → 人工复核放行，或改成 `fits where a full table will not` 结构。
